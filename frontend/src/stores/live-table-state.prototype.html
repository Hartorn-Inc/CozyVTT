Who owns the table when something arrives late?

What should a member at a live session observe when a REST load races a socket update, when the current map changes, when chat never arrives, and when hide or export fails? Compare today’s tangle with a strict split between campaign wiring, the REST cache, and the live-table store.

Recommended: Split. Context keeps identity and clocks (which campaign, which current map, this join). React Query owns REST documents. The live-table store owns tokens and chat. Stale REST and foreign-map socket events are dropped. Failed writes stay on screen and say so. This matches the documented one-datum rule and the reconnect clocks already decided for visibility. Zustand-owns-REST and React-Query-owns-token-frames are not modelled: the first fights every list page; the second cannot take a token slide at sixty frames a second.
