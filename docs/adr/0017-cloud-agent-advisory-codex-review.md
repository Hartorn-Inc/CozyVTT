# Cloud Agent implements; Actions review is advisory

Cloud Agents implement after a collaborator kick: a new GitHub issue comment that starts with `@cursor` plus an instruction (for example `@cursor implement this issue`). The `ready-for-agent` label is the human triage signal that the issue is fully specified; it does not start a Cloud Agent by itself. A label-change Automations trigger (`Issue label changed`, not on PRs) remains the intended path for a label-only kick and is not wired yet. Composer implements, Grok explores via Task, and Luna reviews. Pull requests go only to `dev`, and only write collaborators can open them (`collaborators_only`). Actions [advisory review](../../GLOSSARY.md) is opt-in, not a required check: a no-secret `pull_request` request, then `workflow_run` on `dev`; `/review` is handled on `dev`. Engine, names, and key are [ADR 0018](0018-advisory-review-cursor-cli.md). The inference Environment must be restricted to branch `dev` only (a human GitHub setting; do not add `refs/pull/*/merge`). Outsider triggers are silent GitHub skips. No PAT in Actions, no GitHub App private key in Cursor, and no Instance secrets in Cloud.

**Status**: accepted

**Considered Options**: PAT in Actions; Azure llm-hub keys; OpenRouter workload identity federation; Bugbot as primary review; agent merge; PRs to `main`; prompt-level outsider apologies; secret-bearing `pull_request` YAML. Rejected: WIF is Business/Enterprise only, so the inference key stays in an Environment restricted to `dev` (GitHub job token is still short-lived). The others put org or Instance secrets in Cloud/Actions, let PR YAML name the Environment, make review a merge gate, or duplicate GitHub's collaborator gate in the prompt. Codex-on-OpenRouter as the Actions engine is superseded by [ADR 0018](0018-advisory-review-cursor-cli.md).
