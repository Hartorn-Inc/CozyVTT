# Replace competing authorities first; then scan; then delete only unused leftovers

Cleanup does not start with deletion. **Starter templates** live in the file registry (`GET /api/characters/templates/...`); the validator blank factory is not a second JSON and becomes an alias, then goes. **Published character templates** stay a separate Instance library. **Vibe** uses the dedicated vibe-PUT rules (`enabled`, ≥1 period, unique names, 50-character names) on vibe PUT, campaign PUT, and WebSocket; campaign import omits an illegal vibe with a warning instead of failing the archive; a stored illegal vibe still loads and fails the next vibe write. Toasts are the global `ToastContext` stack; the live table only requires the container outside a CSS `transform`. Live **tokens** belong to the Zustand store (ADR 0011); **current map** is metadata — `GET` map may still send tokens to hydrate on join, map-identity change, or catch-up, but `currentMap.tokens` is not live truth. Sheet header chrome (presets, hex, 4.5:1) is shared; per-**game system** bodies stay. `customLogoUrl` / `logoUrl` stay reserved for Administrator branding. The frontend package is not a public library; documented **Operator** scripts stay. After those replacements, a reference scan may remove orphan UI, the local `components/Toast` hook, unused dice helper in `validation.ts`, leftover blank factories, and similar no-caller exports. Permission helpers, parity file pairs, starter/published routes, and Operator scripts are not deleted from import counts. We rejected merging starters into the published library in this effort, auto-rewriting stored vibes, a second toast system for the map, treating `currentMap.tokens` as live, deprecating `logoUrl`, and supporting npm imports of frontend modules.

**Status**: accepted
