# Remediation is six specced tranches; T1 ships first

The audit program is one specification covering six dependency-ordered tranches, all ticketed before implementation: **T1** security/authorization/privacy (login-session fail-closed, event-time authz, REST/WS write parity, Keeper's Notes off published templates, foreign pings, unreadable assets 404, Character/Campaign game-system match); **T2** UI correctness (stale replies dropped, error ≠ empty success, settings save does not remount); **T3** live table (ADR 0010 clocks plus Focus table C, wide tool rail, DM info at every width); **T4** game systems (ADR 0013); **T5** operations (ADR 0012), which may run in parallel with T2; **T6** cleanup (ADR 0014), always last. Implementation starts at T1. There is no further Wayfinder grilling before `/to-spec`; dialog/form/sheet accessibility is a review gate (WCAG AA, `accessibility-reviewer`), not a new decision ticket. Each implementation ticket uses the existing builder/reviewer roster, keeps OpenAPI/WS docs in the same PR, and names ADR invariant tests. We rejected a security-only spec that leaves later tranches unprepared, a separate OpenAPI tranche, merging T6 early, and completing Shadowrun's sheet or rewriting SRD-safe template prose in this cycle.

**Status**: accepted
